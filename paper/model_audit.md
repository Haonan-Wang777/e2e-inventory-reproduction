# 作者 E2E 模型代码审计

审计范围：`author_package/E2E-model-code/` 的全部 10 个 Python 文件、三个 Data CSV、论文正文第 3.2、4.2 节及附录 B、`original_E2E_section4.pdf` 的历史运行记录。此文档是本次静态审阅记录，不是作者原始说明。

## 结论与复现边界

作者包提供的是**经过保密脱敏的模型框架和少量格式示例**，无法直接运行并重现论文 Section 4 的完整训练与模型成本。可恢复论文公开架构并另写可运行实现；该实现必须标注自选配置和验证数据的来源。少量销售序列可以支持训练流程的烟雾测试，但不支持声称重现 24,333 SKU 主实验或真实供应链效果。

另外，`E2E_Section4.ipynb` 能否重新计算成本须由公开的评估 CSV 单独核验。重新计算历史预测的评估结果，与重新训练原论文模型是两件不同的工作。

## 可核对的论文设计

| 项目 | 论文公开设计 |
|---|---|
| 数据规模 | 食品零食品类 24,333 SKU，单次补货样本 132 维输入 |
| 数据切分 | 按订单创建时间；前 30 天用于训练/验证，其中 80%/20%；后 30 天测试 |
| 主实验成本 | 单位缺货成本 b=9，单位持有成本 h=1 |
| 主要输入 | 需求特征、交付提前期特征、商品/仓库/品牌等基础特征、复核周期、初始库存 |
| 输出 | 补货决策为主输出；需求预测和提前期预测为两个辅助输出 |
| 架构 | 需求子模块 MQRNN；提前期子模块全连接网络；融合模块全连接网络；ReLU 和 dropout |
| 标签 | 已知历史实际需求、下单时点、到货时点后，按定理 1 的事后最优解生成监督标签 |
| 训练目标 | 主决策损失 + 两个小正权重乘辅助预测损失，见公式 (6)；精确损失函数和两个权重未完全公开 |
| 主实验需求预测层级 | 文中写 Q=6，同时列出 mean 与 10%、60%、70%、80%、90%、95%；文字存在六/七输出的歧义，应明确实现选择 |

论文附录表 B.1 提供了以下默认值，优先级应高于脱敏示例脚本中的不同默认值：

| 超参数 | 默认值 |
|---|---:|
| MQRNN 隐状态维度 | 50 |
| 提前期两个隐藏层 | 50, 20 |
| 融合两个隐藏层 | 100, 100 |
| 学习率 | 0.001 |
| 学习率衰减 | 1e-4 |
| Momentum | 0.85 |
| Batch size | 64 |
| 权重初始化 | Gaussian，均值 0、标准差 0.01 |
| 激活 | ReLU |
| Dropout | 0.2 |

历史/预测序列长度、MQRNN context 维度、bridge 大小、辅助损失权重和详细优化器配置仍需自选并记录。论文表 B.1 的 momentum 并不能单独证明作者最终使用哪种优化器；公开训练代码写的是 Adam。

## 源代码阻断与错误

以下行号对应原样保留的作者包。

| 位置 | 发现 | 对复现的影响/建议 |
|---|---|---|
| `configs/config.py:11` 等 | 多处未加引号的 `DISGUISED FEATURE DETAILS`；62-68 行超参也未定义 | `ast.parse` 已确认第 11 行语法错误，导入任何模型前即失败；需另建公开配置 |
| `utils/demand_pkg.py:134` | `DISGUISED WINDOW LIST` 语法错误 | 特征生成不能运行；窗口需显式配置 |
| `models/model.py:158-168` | `Dimension`、`FULLY_CONNECTED_LAYER` 全为未定义占位符；`fc_4` 重复赋值 | 需依据公开架构补全具体层，而非只安装依赖 |
| `models/model.py:135` | `hidden_bridge = result.view(...)` 覆盖真实 bridge，使用了需求预测输出 | Decoder 中独立 bridge 层失去作用；实现应保留 decoder 返回的 bridge，并核对融合维度 |
| `models/model.py:134-135` | reshape 使用全局 `rnn_pred_long` 与 `num_quantiles`，而非实例属性 | 修改实例参数时形状可能错误；需使用实例维度 |
| `models/model.py:131` | 将 LSTM `ht` 直接 view 成 `(batch, hidden)` | 仅适用单层单方向；若扩展层数应取最后一层 |
| `models/model.py` | 与论文描述不同，代码中未实现 dropout | 新实现可采用论文默认 0.2，并说明属于公开设计恢复 |
| `models/loss.py:78-87` | `VALUE1/2`、`LOSS_FUN1/2/3` 未定义 | 主/辅助损失和权重保密，需要自选并披露 |
| `models/loss.py:85-91` | 设置 `self.q_loss`，随后引用不存在的 `self.qtl_loss` | 即使填补占位符，forward 仍会报错 |
| `models/loss.py:73` | 参数 qtl 传入后未保存 | 不能从该代码推定主决策损失实际分位水平 |
| `mains/main.py:19` | 顶层使用 TensorFlow 1 风格 `tf.app.flags`，PyTorch 入口仍触发它；model.py 还导入未使用的 tensorflow/torchvision | 需要旧 TensorFlow 兼容或移除无关依赖；独立 PyTorch 实现更易运行 |
| `mains/main.py:111` | 默认恢复 `e2e_v6_10.pkl`，包内无此 checkpoint | 默认启动也不是从头训练；应显式设置无恢复或另写入口 |
| `data_loader/data_loader.py:108` | 要求 `1320_feature/df_e2e.pkl`，包内没有 | 真实训练样本缺失 |
| `data_loader/data_loader.py:28-29` | `df_train=o2`，测试集为同一数据前 1000 行；传入 sku_train/sku_test 实际未用于筛选 | 严重训练/测试重叠，与论文时间切分不同 |
| `trainers/train_tc.py:57` | 又将 `test_loader = data_loader` | 显示的 test loss 实际是训练集损失，不可用于模型泛化结论 |
| `trainers/train_tc.py:60` | `qtl=b/(b+1)-0.1` | 与普通 critical ratio 不同；论文未给出该减 0.1 的理由，不能直接当成公开理论公式 |
| `trainers/train_tc.py` | 验证没有 `model.eval()`/`torch.no_grad()` | 加入 dropout 后必须修正；原样评估不可用作规范验证 |
| `trainers/train_tc.py` | Unix `rm`/`mkdir`、输出路径硬编码、传入 data_path 未用于 get_loader | Windows 运行和路径切换会失败；应使用 pathlib 并显式传路径 |
| `data_loader/data_parser.py:36` | 要求 CSV 日期字段 `dt`，提供的交付 CSV 无此列 | 原始格式示例不能直接进入处理器 |
| `data_loader/data_parser.py:130` | 下一个 review period 用全表 diff，未按 SKU 分组 | 多 SKU 时会跨组计算错误，应 groupby 后 shift |
| `data_loader/data_parser.py:164` | add_target 函数只保留说明，没有标签计算 | 需实现定理 1，不能认为包内已有标签算法 |
| `data_loader/data_parser.py:228-234` | dummy_cut 只保留说明，却 pickle 未定义的 o2r | 无法生成训练 pickle |
| `data_loader/data_parser.py:194-224` | 时间序列按闭区间切片，`lw` 可能得到 `lw+1` 点；列表通道排布随后直接 reshape | 必须统一日期边界并显式 transpose/stack，不能假定 reshape 自动转换通道次序 |

脚本语法验证：10 个 `.py` 文件中，`config.py` 和 `demand_pkg.py` 解析失败，其余 8 个仅通过语法解析；通过语法不代表可运行。

## 三个 Data 示例的实测范围

| 文件 | 实际范围 | SKU ID |
|---|---|---|
| `Data/rdc_sales_1320.csv` | 5 条销售序列，每条 457 天（列 1520-1976） | `1111111#1`、`2222222#1`、`3333333#1`、`4444444#1`、`5555555#1` |
| `Data/stock.csv` | 2 条库存序列，2019-03-01 至 2019-03-31 共 31 天 | `10000000#1`、`20000000#1` |
| `Data/vlt_2019_0305.csv` | 1 个订单；含 17 列，多项保密属性为空 | 原 item_sku_id=`111111`，仓库=`1`；拼接后为 `111111#1` |

三张表没有相同的 SKU#DC 主键，不能生成真实对齐的训练订单。一个提前期观测也不能训练或评估提前期预测模型。销售天数足够切出多个相邻窗口，但同一商品高度重叠的窗口绝不能当成数千个独立商品样本。

## 诚实的可运行演示方案

1. 原样保留作者包，在独立目录实现恢复后的 MQRNN + 提前期 MLP + 融合决策网络。
2. 使用五条公开销售序列进行训练流程测试；若需要补货时点、提前期、库存和类目输入，必须明确标为**人工构造的实验条件**，不可使用不匹配的 SKU 表假装真实连接。
3. 用按时间排列且边界明确的训练、验证、测试窗口；归一化只在训练集拟合。若目标区间跨越切分边界则丢弃样本。
4. 按定理 1 生成标签时，明确当前库存所对应的时点为到货时点、需求区间为当前到货至下次到货之前；不得把多期问题简化为普通单期需求分位数而仍称为精确原算法。
5. 至少验证：张量形状正确，损失和梯度有限，所有相关子模块存在梯度，权重更新，短期训练损失下降，checkpoint 可恢复，保留集计算互不重叠。
6. 模型输出、训练曲线、toy held-out 成本仅说明实现可运行。论文图 2 的 E2E 成本 3766.520059 若由公开历史预测再算出来，应归类为“评估重算”，不能归类为“模型重新训练复现”。

## 若要完成原始训练复现，仍需的材料

- 完整且可关联的商品日需求、订单创建/到货、历史库存、类目/仓库/供应商等数据，或与论文一致的 `df_e2e.pkl`。
- 132 维特征映射、MQRNN 序列/分位配置、bridge 结构、缺失初始化以及完整损失/权重。
- 完整时间切分规则与超参选择记录，含与论文/历史日志日期不一致的说明。
- 作者模型 checkpoint 或允许从头训练所需的全部原始参数。

历史 PDF 中记录的 2018 年训练切分与示例 CSV 的 2019 年日期不一致，不能混用。这些缺口属于资料限制，不应通过自行造数来掩盖。
